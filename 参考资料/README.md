## 法规底线（方案必须遵守）

依据《招标投标法》《招标投标法实施条例》《电子招标投标办法》：

1. **评标主体是评标委员会**，AI 只能辅助，不能自动确定中标人。
2. 否决投标必须有招标文件明确依据；抽取不清时结论应为「待专家复核」，不得机器否决。
3. 评标过程保密、独立评审；系统需隔离专家之间未汇总前的打分，并留存操作日志。
4. 评标报告、否决理由、评分明细必须可追溯到文件原文（页码/条款）。
5. 电子评标系统应保证投标文件解密后仅评标委员会可见，过程数据防篡改。

## 行业产品能力对照（广联达 / 新点等常见模块）

典型「智能辅助评标」不替代电子招投标交易平台，而是叠在开标之后：

1. **清标**：报价清单规范化、算术性错误、漏项、不平衡报价、与招标控制价偏离。
2. **资格/符合性审查**：营业执照、资质、业绩、人员、保证金、响应偏离表。
3. **评分辅助**：按评分办法拆条，定位投标文件证据，给出建议分 + 依据。
4. **围标串标预警**：文件元数据/作者/创建时间、文本相似度、报价规律、IP/MAC（若有电子标）。
5. **专家工作台**：分项打分、横向对比、澄清问卷草稿、评标报告汇编。

## 对本项目的启示

- 不要做完整电子招投标（报名、CA、远程开标、电子签章）——那是交易平台，周期以年计。
- 核心产品应是「开标后的专家辅助评标智能体」：结构化招标办法 → 对照投标文件 → 证据化建议 → 专家确认 → 评标底稿。
- 决策语义必须三态：`通过 / 不通过 / 待复核`，与 tender-ai 的 Passed/Failed/Review 同构。
- 技术栈若对齐本机已有「物料管理智能体」（FastAPI + Vue3 + Docker + 内网 LLM 网关），复用成本最低。
